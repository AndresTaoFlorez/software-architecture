# Software Architecture Reference

A handbook for programmers learning how to separate business decisions, application workflows and technical mechanisms. It explains responsibilities, dependencies and file placement through small examples.

## Where to start

Read [Foundations](architecture/foundations/README.md), then choose a frontend or backend route. Use the [Glossary](GLOSSARY.md) as a reference and [Contributing](CONTRIBUTING.md) for the editorial standard.

| Area | What you will find |
| --- | --- |
| [Architecture](architecture/README.md) | The handbook's main learning routes |
| [Foundations](architecture/foundations/README.md) | Ownership, placement, dependencies and public APIs |
| [Styles](architecture/styles/README.md) | Clean and Onion Architecture |
| [Presentation patterns](architecture/patterns/presentation/README.md) | MVC and MVVM |
| [Frontend](architecture/frontend/README.md) | React presentation, state and external integrations |
| [Backend](architecture/backend/README.md) | TypeScript boundaries, HTTP delivery and Nest composition |
| [Conventions](architecture/conventions/README.md) | Naming and guide structure |
| [Extras](extras/README.md) | Scope for adjacent disciplines taught separately |

This repository contains documentation and illustrative snippets. It has no application, package manager or committed validation runtime.
