## Navigation repair after PR #23

The deployed sidebar contained empty autogenerated groups because Starlight's directory lookup assumes its standard collection location. Canonical Markdown is loaded from outside that location. Commit `54bc00b` replaces directory autogeneration with explicit slugs derived from the canonical inventory, preserving nested groups and real source paths. The new build regression failed against the previous artifact and passed after the repair: all 101 reader pages appear in the sidebar and no disclosure group is empty.

Windows validation of that repair passed Astro/TypeScript checks (34 files, no diagnostics), the 102-page build, 25 tests, 15,540 local links/fragments, HTTP preview smoke and the real filesystem watcher. After adding native CSS smooth scrolling, the build, 25 tests and preview smoke passed again. The existing reduced-motion override remains authoritative.

Local headless Edge interaction checks used 1440×900 and 390×844 viewports. Desktop disclosure controls closed with a click and reopened with Enter. A sidebar link reached Code Placement, marked the current page and returned through browser Back. Mobile navigation opened the menu, closed/reopened Frontend, reached Presentation Architecture and hid the menu after navigation. Sampled desktop/mobile screenshots showed populated nested navigation without horizontal document overflow. A TOC click in Code Placement changed the fragment and progressed from scroll position 0 to 860; computed document behavior was `smooth`. Emulated reduced motion changed it to `auto`, and the Overview link returned to the top. These checks cover sampled native navigation, not every possible link or a screen-reader audit. Smooth scrolling applies to document anchors, not transitions between pages.

These are local candidate checks. Publication requires a separately authorized merge and a successful Pages deployment; this section does not claim the navigation repair is live.
