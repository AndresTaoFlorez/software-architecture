# API Design Exercises

Work from the public behavior back to the owner of each decision. Use the clinic contract in the [API Design route](../README.md). The exercises are reasoning and focused code changes, not a runnable application in this repository.

1. [Foundations](foundations.md) — interpret endpoints and methods after [HTTP and Identifiers](../http-and-identifiers.md); complete the third exercise after [Resources and Operations](../resources-and-operations.md).
2. [Design](design.md) — choose resources, updates, pagination and time semantics after [Resources and Operations](../resources-and-operations.md).
3. [Engineering](engineering.md) — repair boundaries, isolate tenants, handle races and evolve a contract after the [security](../security-and-tenancy.md) and [reliability](../reliability-and-operations.md) chapters.

Compare your work with the separate [solutions](solutions.md) only after you have written a request/response example or changed the focused excerpt. A different design can be valid if it preserves HTTP semantics, the clinic rules and an explicit consumer contract.
